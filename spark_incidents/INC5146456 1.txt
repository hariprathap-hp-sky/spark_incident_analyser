Incident ID: INC5146456
Date: 17/03/2026 
Short Description: NAP: Streamwide Plugin Error

Description: 
	- NAP is currently receiving intermittent plugin errors from Streamwide. The error message seen in the logs is "Failed to invoke plugin [voice]. This impacts all provisioning going to Streamwide like activate_subscriber, activate_account, cease_subscriber, number_import, number_port_out and number_port_out_cease. 
	- This is because of some heap issues in the Streamwide pods.  As things stand, the temporary fix is to restart the pods in that particular site which will fix the issue. But the issue comes back again after a week or so. 
	- Amdocs are working on a permanent solution to fix this. We will keep this incident open to track the updates regarding the fix. 

Resolution:
	- Fix is delivered
    - Fixed has been deployed in the machine by upgrading the libraries

Work Notes:
	- This issue is occurring because , earlier, the Streamwide interface used a static URL, for example:
	https://10.111.222.3:4444/swums_rpc/server.php
	- However, after the VSL migration, the connectivity URLs became dynamic, such as:
	https://10.11.22.33:4444/vmsxml/xmlprofile.php/{MSISDN}
	- Because of this change, each time NAP receives a provisioning request for Streamwide, a new connection pool instance gets created - since the MSISDN value is appended to the URL. As a result, NAP treats each request as a new connection, leading to multiple pool creations and faster memory utilization.
	- To address this, I’ve implemented a code fix where the MSISDN portion is trimmed from the URL before establishing the connection. This ensures that the connection URL remains static for NAP, resulting in a single, limited connection pool. For all other operations, the full URL (including MSISDN) is still used as expected.
